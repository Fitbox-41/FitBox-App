# Handoff — 29 July 2026 (App + Website + Admin)

Summary of everything changed across the three repos in this round, and the
action items on your side. Everything is deployed to `main` on all three repos
(Vercel auto-deploys).

## What changed (all deployed)

### 1. Points economy (app + website)
- **1 point = ₹0.10** (was ₹2). Points redeem for **at most 50%** of an order;
  the rest must be paid.
- App backend credits **10 points per km** on a saved run (`backend/routes/runs.js`),
  ledgered in `wallet_transactions` with an idempotency key.
- Website `Backend/Controllers/orderController.js`: the 50% cap is enforced
  server-side, computed on the **pre-discount order value** (reconstructed from
  `totalAmount + requestedPoints·0.10`) so the client preview matches the server
  clamp exactly.
- Website `Frontend/src/pages/Cart.jsx`: shows ₹0.10, the 50% cap, and the
  applied discount (was still on the old ₹2 / no-cap logic — that mismatch is
  fixed).
- Website Terms page: added a **"FitBox Points & Rewards"** clause (no cash
  value, ₹0.10, 50% limit, earn/expiry/misuse/refund). **Please keep this** —
  it's there for legal safety. Also there's a points T&C dialog in the app wallet.

### 2. Challenges (app + admin)
- New collections: **`challenges`** and **`challenge_progress`** (see
  `backend/models/Challenge.js`, `ChallengeProgress.js`).
- App: a **Challenges** screen (join / progress / claim). Users earn the
  challenge's `rewardPoints` on completion; a `userCap` limits how many get the
  reward ("first N users").
- Admins create/edit/delete challenges from the admin portal (see below).
  Challenge admin endpoints are service-key gated.

### 3. Territory — weekly seasons (app backend)
- `Territory` now has a **`season`** field (ISO week, e.g. `2026-W31`); the
  unique index changed from `{userId}` to **`{userId, season}`**.
- Map + leaderboard count only the current season, so territory **auto-resets
  every Monday 00:00 UTC** (past weeks are kept as history). No cron — it's
  date-derived. `GET /api/territories` now returns `season` + `seasonEndsAt`.

### 4. True background run (app)
- The GPS stream runs under a **location foreground service** (Android) so the
  run keeps recording (timer + steps + route) when backgrounded / screen-off;
  iOS opts into background location (`UIBackgroundModes`). New Android perms:
  `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_LOCATION`, `WAKE_LOCK`.

### 5. Push notifications — FCM (app + backend + admin)
- App: `firebase_core` + `firebase_messaging`; device token registered per
  signed-in user (`fcmTokens[]` on the shared `users` doc).
- App backend: `firebase-admin` sender (`backend/fcm.js`) + `backend/routes/push.js`
  (`/register`, `/unregister`, service-key `/send`, public `/status`). Territory
  capture pushes an "under attack / lost" notification to contested users.
- Admin: a **Push composer** (all users / single user).

### 6. Admin portal — new "FitBox App" section
- Sidebar → **FitBox App** (`/app`): Overview (analytics), Users, Challenges
  (CRUD), Push, Territory. Backend `Backend/routes/app.js` (`/api/app/*`):
  analytics/users/territory read the shared DB directly; challenges + push proxy
  to the app backend with the shared service key.

## Addendum — later the same day

- **User segregation (admin).** Admin **Customers** = website users; **FitBox App → Users** = app
  users; a real dual-user appears in both. Signals: the app backend stamps `lastAppLoginAt` on any
  authenticated request; the website stamps `lastWebLoginAt` when the request carries `X-Client: web`.
  - **Keep `X-Client` in the website CORS `allowedHeaders`** (`Backend/server.js`). Removing it breaks
    all website logins (the header triggers a CORS preflight). If you add other custom headers on
    app→website or web→backend calls, allow them there too. (Reminder: keep app web origins allowlisted.)
  - The website frontend sets `X-Client: web` by default (`Frontend/src/main.jsx`).
  - `POST /api/appmaint/tag { email, app, web }` (service-key) manually tags known users.
- **Wallet page (website).** New `/account/wallet` with full history + CSV/print-to-PDF export (no new
  deps). The account page shows a summary + "View all" link.
- **Admin bonus example.** `POST /api/wallet/credit` now also accepts `{ email }` (not just `userId`)
  for admin point grants; idempotent via `idempotencyKey`.
